# 06. 出力仕様

出力先: `{OutputDir}\yyyyMMdd_HHmmss\`（実行ごとに新しいフォルダ）

| ファイル | 文字コード | 常に出力 | 内容 |
|---|---|---|---|
| `prs.csv` | UTF-8 BOM 付き | ○ | PR の明細 |
| `summary_by_period.csv` | UTF-8 BOM 付き | ○ | 期間別の集計 |
| `summary_by_author.csv` | UTF-8 BOM 付き | ○ | 作成者別の集計 |
| `run_info.json` | UTF-8 | ○ | 実行条件の記録 |
| `raw_pullrequests_{リポジトリ}.json` | UTF-8 | `SaveRawJson=$true` のとき | API の PR 一覧そのもの（`-ReplayDir` で再利用可） |

- CSV はすべての値を `"` で囲む。値が無い（計算できない）項目は**空欄**（0 ではない）。
- 日時は設定タイムゾーン（既定: 日本時間）で `yyyy-MM-dd HH:mm`。
- 数値の小数は 2 桁に丸める。

---

## 1. prs.csv

PR 1 件 = 1 行。リポジトリ名、PR 番号の順に並ぶ。

| 列 | 例 | 説明・計算式 |
|---|---|---|
| `Repository` | `SampleRepo` | リポジトリ名 |
| `PullRequestId` | `1234` | PR 番号 |
| `Title` | `機能A追加` | タイトル |
| `Status` | `completed` | `completed` / `abandoned` / `active` |
| `IsDraft` | `False` | Draft か |
| `Author` | `山田 太郎` | 作成者の表示名 |
| `AuthorId` | `yamada@example.co.jp` | 作成者の一意名（集計のキー） |
| `SourceBranch` | `feature/xxx` | ソースブランチ（`refs/heads/` を除く） |
| `TargetBranch` | `main` | マージ先ブランチ |
| `CreatedAt` | `2026-09-01 09:00` | 作成日時 |
| `ClosedAt` | `2026-09-02 15:00` | 完了日時（未完了は空欄） |
| `Period` | `2026-08-31` | 属する集計期間のラベル（基準日から計算） |
| `LeadTimeHours` | `30` | `ClosedAt − CreatedAt`（時間） |
| `ReviewerCount` | `2` | レビュアー数（グループを除く） |
| `ApprovedCount` | `1` | 承認したレビュアー数（vote が 10 または 5） |
| `FilesChanged` | `5` | 変更ファイル数（除外を除く、バイナリを含む） |
| `LinesAdded` | `120` | 追加行数（Git 方式のみ） |
| `LinesDeleted` | `30` | 削除行数（Git 方式のみ） |
| `LinesChanged` | `150` | `LinesAdded + LinesDeleted` |
| `BinaryFiles` | `0` | バイナリファイル数（Git 方式のみ） |
| `ExcludedFiles` | `1` | 除外パターンに一致したファイル数 |
| `SizeCategory` | `M` | サイズ区分（行数、無ければファイル数で判定） |
| `SizeSource` | `git:target..merge` | サイズの計算方法（下表） |
| `SizeNote` | | 補足（フォールバックや失敗の理由） |
| `MergeStrategy` | `squash` | マージ方法（`noFastForward` / `squash` / `rebase` / `rebaseMerge`） |
| `Url` | `https://dev.azure.com/.../pullrequest/1234` | PR の画面 URL |

`SizeSource` の値:

| 値 | 意味 |
|---|---|
| `git:target..merge` | マージ先コミット → マージコミットの差分（最も正確） |
| `git:base...source` | 共通祖先 → ソースコミットの差分（フォールバック） |
| `api` | API の変更ファイル一覧（行数なし） |
| `none` | `SizeMethod=None` |
| `unavailable` | 計算できなかった（理由は `SizeNote`） |

## 2. summary_by_period.csv

（リポジトリ × 期間）= 1 行。PR が 0 件の期間も出力する。リポジトリが複数のときは `Repository=(ALL)` の行も出す。

| 列 | 説明・計算式 |
|---|---|
| `Repository` | リポジトリ名 または `(ALL)` |
| `Period` | 期間のラベル（週: 開始日 `yyyy-MM-dd`、月: `yyyy-MM`、日: `yyyy-MM-dd`） |
| `PrCount` | 件数 |
| `AuthorCount` | 作成者数（重複なし） |
| `LeadTimeMedianH` / `LeadTimeAvgH` | リードタイムの中央値 / 平均（時間） |
| `FilesChangedMedian` | 変更ファイル数の中央値 |
| `LinesChangedMedian` / `LinesChangedAvg` / `LinesChangedTotal` | 変更行数の中央値 / 平均 / 合計 |
| `Size_{区分名}` | 区分ごとの件数（`SizeCategories` の定義に合わせて列が増減） |
| `SizeUnknown` | サイズ区分が判定できなかった件数 |

統計値は「値がある PR だけ」で計算する（サイズ不明の PR は中央値の計算に入らない）。

## 3. summary_by_author.csv

（リポジトリ × 作成者）= 1 行。件数の多い順。

| 列 | 説明・計算式 |
|---|---|
| `Repository` | リポジトリ名 または `(ALL)` |
| `Author` / `AuthorId` | 作成者 |
| `PrCount` | 件数 |
| `PrPerWeek` | `PrCount ÷ (集計日数 ÷ 7)` |
| `LeadTimeMedianH` | リードタイム中央値 |
| `LinesChangedMedian` / `LinesChangedTotal` | 変更行数の中央値 / 合計 |
| `FilesChangedMedian` | 変更ファイル数の中央値 |

> 作成者別の数値は、チームの傾向をつかむためのもので、個人の評価に使う指標ではありません。PR の粒度は担当範囲によって変わります。

## 4. run_info.json

```jsonc
{
  "ExecutedAt": "2026-10-02 15:01:05",
  "PowerShellVersion": "5.1.26100.9444",
  "ConfigPath": "C:\\...\\config\\settings.psd1",
  "ReplayDir": "",
  "FromLocal": "2026-07-05",
  "ToLocalInclusive": "2026-10-02",
  "Repositories": [ { "Repository": "SampleRepo", "Fetched": 120, "Included": 115 } ],
  "TotalPrs": 115,
  "Config": { /* 実際に使った設定値（PAT は含まない） */ }
}
```

`Fetched` は API から取得した件数、`Included` は絞り込み後の件数。差が大きいときは、絞り込み条件か `UseServerSideDateFilter` の動作を確認する。

## 5. Excel での活用例

1. `summary_by_period.csv` を開く → 挿入 → グラフ → 縦棒（`Period` × `PrCount`）で **頻度の推移**
2. 同じく `Size_XS`〜`Size_XL` を積み上げ縦棒にすると **サイズ構成の推移**
3. `prs.csv` をテーブルにして `LinesChanged` で並べ替え → 大きい PR の確認（`Url` 列から PR を開ける）
4. `prs.csv` をピボットテーブルにして、`TargetBranch` × `Period` などの独自の集計
