# 05. 詳細設計

関数単位の仕様です。コードを修正するときは、この資料と関数のコメント（`<# .SYNOPSIS #>`）を一緒に更新してください。

## 0. コーディング規約

| 項目 | ルール | 理由 |
|---|---|---|
| 対応バージョン | PowerShell 5.1 と 7 の両方 | 会社 PC 標準は 5.1 |
| 使わない構文 | `??`, `?.`, 三項演算子 `a ? b : c`, `ConvertFrom-Json -AsHashtable`, `Join-Path` の 3 引数以上, `&&`/`\|\|` | 5.1 で構文エラーになる |
| 文字コード | `.ps1` / `.psd1` は **UTF-8 BOM 付き** | BOM 無しは 5.1 で Shift-JIS 扱い |
| StrictMode | 使わない | API の JSON は項目が欠けることがあり、`$obj.無い項目` を `$null` として扱う前提 |
| プロパティの存在確認 | 必要な箇所は `$obj.PSObject.Properties['name']` | 欠けている項目と `$null` を区別するため |
| 関数の戻り値 | 配列は普通に出力する（`return , $array` は使わない）。呼び出し側で `@(...)` で受ける | `return , $x` は `@()` で受けると配列の配列になる |
| 外部コマンド | git は必ず `Invoke-Git` 経由で呼ぶ | 文字コード・エラー処理・終了コードの扱いを統一 |
| 秘密情報 | PAT・認証ヘッダーを `Write-Host` / `Write-Verbose` / ファイルに出さない | セキュリティ |
| 命名 | 関数は `動詞-名詞`（承認された動詞: Get/New/Test/ConvertTo/Invoke/Export/Import/Resolve/Initialize/Write） | PowerShell の慣例 |

## 1. Invoke-PrMetrics.ps1（エントリポイント）

### 引数

| 引数 | 型 | 既定 | 説明 |
|---|---|---|---|
| `ConfigPath` | string | `config\settings.psd1` | 設定ファイル |
| `Mode` | `Collect` \| `TestConnection` | `Collect` | 動作モード |
| `FromDate`, `ToDate` | string | — | 期間の上書き |
| `Repositories` | string[] | — | リポジトリの上書き |
| `SizeMethod` | `Git` \| `Api` \| `None` | — | 方式の上書き |
| `ReplayDir` | string | — | 保存済み JSON のフォルダ |

### 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常終了（接続確認ではすべて OK） |
| 1 | エラー終了、または接続確認で NG あり |

### 処理（Collect）

1. `src\*.ps1` を dot-source で読み込む
2. PowerShell 5.1 なら TLS1.2 を有効にする
3. `Import-PrMetricsConfig`（引数で上書き）→ `Get-PrMetricsDateRange`
4. `ReplayDir` が無い、または `SizeMethod=Api` のとき PAT を取得し `New-AzDoContext`
5. 出力フォルダを作成
6. リポジトリごとに:
   1. PR 一覧取得（`Statuses` の各ステータスについて `Get-AzDoPullRequests`）。`ReplayDir` なら JSON を読む
   2. `SaveRawJson` なら保存
   3. `Test-PullRequestIncluded` で絞り込み
   4. Git 方式なら `Initialize-GitRepository`
   5. PR ごとに:
      - Git 方式で一覧に `lastMergeTargetCommit` が無ければ `Get-AzDoPullRequest` で補完
      - サイズ計算（例外は捕まえて `unavailable` として続行）
      - `ConvertTo-PrRecord`
7. `Get-PeriodSummary` / `Get-AuthorSummary`
8. CSV 3 種と `run_info.json` を出力、要約を表示

### 処理（TestConnection）: `Invoke-ConnectionTest`

| No | 確認項目 | 方法 | NG のときの意味 |
|---|---|---|---|
| 1 | リポジトリ取得 | `Get-AzDoRepository` | PAT・組織・プロジェクト・リポジトリ名の誤り |
| 2 | PR 一覧取得 | `status=all&$top=1` | 権限不足 |
| 3 | 期間指定（サーバー側） | `minTime/maxTime/queryTimeRangeType` 付きで 1 回 | サーバーが未対応 → `UseServerSideDateFilter=$false` |
| 4 | 一覧にマージコミット情報（INFO） | 最新 PR に `lastMergeTargetCommit` があるか | 合否には影響しない。無ければ個別取得になり遅くなる |
| 5 | サイズ(Api)（Api 方式のみ） | 最新 PR で `Get-PrSizeFromApi` | イテレーション API の権限・仕様差 |
| 6 | git コマンド（Git 方式のみ） | `git --version` | Git 未インストール |
| 7 | git 認証（Git 方式のみ） | `git ls-remote --heads {remoteUrl}` | 資格情報・プロキシ |
| 8 | ローカル clone（Git 方式のみ） | フォルダの有無 | （情報のみ） |

## 2. Config.ps1

### `Import-PrMetricsConfig -Path <string> [-Overrides <hashtable>]` → hashtable

1. `Import-PowerShellDataFile` で読み込み
2. `Overrides` のうち、`$null`・空文字・空配列ではない値で上書き
3. 書かれていない項目に `$script:PrMetricsDefaultConfig` の既定値を補う
4. 配列項目（`Repositories` など）を `@(...)` で配列に正規化し、空要素を除く
5. `Test-PrMetricsConfig` で検証

### `Test-PrMetricsConfig -Config <hashtable>`

- エラーは**すべて集めてから**まとめて例外にする（1 個ずつ直して何度も実行しなくて済むように）。
- 検証内容: 必須項目、列挙値（`DateBasis`, `PeriodUnit`, `SizeMethod`, `WeekStartDay`, `Statuses`）、日付形式 `yyyy-MM-dd`、`LastNDays>0`、タイムゾーン ID の存在、`PageSize` 1〜1000、`SizeCategories` の形。
- 警告: `DateBasis='Closed'` かつ `Statuses` に `active` がある（active は完了日が無く集計されない）。

### `Get-PrMetricsDateRange -Config -TimeZone [-NowUtc]` → object

| 出力項目 | 説明 |
|---|---|
| `FromLocal` | 期間開始（設定タイムゾーンの 0:00） |
| `ToLocalExclusive` | 期間終了の**翌日** 0:00（この時刻は含まない） |
| `FromUtc` / `ToUtcExclusive` | 上記を UTC に変換したもの |
| `Days` | 日数 |

例（日本時間・`FromDate=2026-09-01`, `ToDate=2026-09-30`）:
`FromUtc = 2026-08-31T15:00Z`, `ToUtcExclusive = 2026-09-30T15:00Z`, `Days = 30`

`-NowUtc` はテストで「今日」を固定するための引数。

### `ConvertTo-UtcDateTime <value>` → datetime or $null

PowerShell 7 の `ConvertFrom-Json` は ISO 8601 文字列を自動で `[datetime]` に変換するが、5.1 は文字列のまま。両方を受け付ける。

| 入力 | 出力 |
|---|---|
| `$null` / 空文字 | `$null` |
| 文字列 `2026-09-01T00:00:00.123Z` | UTC の datetime |
| datetime（Kind=Local） | `.ToUniversalTime()` |
| datetime（Kind=Utc/Unspecified） | Kind を Utc にしたもの |
| 2000 年より前（`0001-01-01` など） | `$null`（未設定扱い） |

## 3. AzDoClient.ps1

### `Get-AzDoPat -Config` → string

環境変数を **プロセス → ユーザー** の順に探す。無ければ `Read-Host -AsSecureString` で入力させる（表示しない）。

### `New-AzDoContext -Config -Pat` → object

| 項目 | 内容 |
|---|---|
| `ProjectUrl` | `{BaseUrl}/{Organization}/{Project}`（各要素は URL エンコード） |
| `Headers` | `Authorization: Basic ...`, `Accept: application/json` |
| `BasicToken` | git の extraHeader 用 |
| `Proxy`, `ProxyUseDefaultCredentials`, `MaxRetry`, `RetryWaitSeconds` | 設定値 |

### `Invoke-AzDoApi -Context -Path [-Query]` → object（JSON を変換したもの）

```
URL = {ProjectUrl}/_apis/{Path}?api-version={ApiVersion}&{key=URLエンコード(value)}...
```

- `Query` のキーはそのまま（`$top` など）、値は URL エンコードする。値が `$null`/空文字のキーは付けない。
- `Invoke-WebRequest -UseBasicParsing` を使い、**応答のバイト列を UTF-8 として自前でデコード**する。
  （5.1 の `Invoke-RestMethod` は charset の扱いで日本語が化けることがあるため）
- Content-Type に `json` が無ければ例外（PAT 無効時の 203 + HTML 対策）。
- 再試行の判定:

```
ステータス不明(通信エラー) / 429 / 5xx  → 再試行（待ち = RetryWaitSeconds × 2^(試行回数-1)）
それ以外 / 再試行回数超過               → Get-AzDoErrorHint でヒント付きメッセージを作って例外
```

### `Get-AzDoPullRequests -Context -Repository -Status -FromUtc -ToUtcExclusive -DateBasis [-PageSize] [-ServerSideDateFilter]` → PR[]

```
skip = 0
繰り返し:
    API 呼び出し（status, $top=PageSize, $skip=skip, [期間パラメーター]）
    結果を追加、skip += 取得件数
  取得件数 < PageSize になったら終了
```

### その他

| 関数 | API | 戻り値 |
|---|---|---|
| `Get-AzDoRepository` | リポジトリ取得 | リポジトリ |
| `Get-AzDoPullRequest` | PR 個別取得 | PR |
| `Get-AzDoPullRequestIterations` | イテレーション一覧 | イテレーション[] |
| `Get-AzDoPullRequestIterationChanges` | 変更一覧（`nextSkip` でページング、`$top=2000`） | changeEntry[] |

## 4. SizeCalculator.ps1

### サイズ結果オブジェクト（`New-PrSizeResult`）

| 項目 | 型 | 説明 |
|---|---|---|
| `FilesChanged` | int / $null | 変更ファイル数（除外を除く、バイナリを含む） |
| `LinesAdded` / `LinesDeleted` | int / $null | 追加・削除行数（Git 方式のみ） |
| `LinesChanged` | int / $null | 追加 + 削除（両方あるときだけ計算） |
| `BinaryFiles` | int / $null | バイナリファイル数 |
| `ExcludedFiles` | int / $null | 除外パターンに一致したファイル数 |
| `SizeSource` | string | 計算方法: `git:target..merge` / `git:base...source` / `api` / `none` / `unavailable` |
| `SizeNote` | string | 補足（フォールバックした理由・失敗理由・イテレーション番号） |

### 4.1 Git 方式のアルゴリズム（`Get-PrSizeFromGit`）

PR オブジェクトの 3 つのコミット ID を使う:

```
T = lastMergeTargetCommit  … マージ時点のマージ先ブランチの先端
S = lastMergeSourceCommit  … ソースブランチの先端
M = lastMergeCommit        … T と S をマージした結果のコミット
```

```
        (main)  ──●──●──T──────M      ← 通常マージ: M の親は T と S
                      \       /
       (feature)       ●──●──S

        (main)  ──●──●──T──M          ← squash: M の親は T だけ（S の内容をまとめたもの）
```

**戦略 1: `git:target..merge`（優先）**

```
git diff --numstat -M T M
```

M は「T に PR の変更を加えたもの」なので、`T→M` の差分がそのまま **PR が持ち込んだ変更**。
マージ先で並行して進んだ変更は T に含まれているので、差分に混ざらない。通常マージでも squash でも同じ式で計算できる。

**戦略 2: `git:base...source`（戦略 1 ができないとき）**

```
git diff --numstat -M T...S      （= merge-base(T,S) から S までの差分）
```

ソースブランチ側の変更を、分岐点から数える。M が取得できない場合（未完了 PR の古いマージプレビューなど）に使う。

**コミットの入手（`Test-GitCommitAvailable`）**

```
git cat-file -e {sha}^{commit}        … ローカルにあるか
  無く、FetchMissingCommits=$true なら
git fetch --quiet origin {sha}        … SHA を指定して取得を試みる ⚠
git cat-file -e {sha}^{commit}        … 再確認
```

⚠ SHA 指定の fetch は、サーバーがそのコミットを公開している（どこかの ref から到達できる）場合だけ成功する。
削除されたブランチにしか無いコミットは取れないことがある → 戦略 2 も失敗 → `unavailable`。

**`ConvertFrom-GitNumstat`**

`git diff --numstat` の 1 行 = `追加数<TAB>削除数<TAB>パス`

| 行の例 | 扱い |
|---|---|
| `10	2	src/a.c` | 追加 10・削除 2・ファイル 1 |
| `-	-	img/logo.bin` | バイナリ: ファイル 1・バイナリ 1（行数は加えない） |
| `3	3	src/{old => new}/b.c` | リネーム: 変更後のパス `src/new/b.c` で除外判定 |
| `5	0	out/fw.hex`（`*.hex` 除外時） | 除外 1（ファイル数・行数に加えない） |

- `-c core.quotepath=false` を付けて、日本語ファイル名がエスケープされないようにする。
- git の出力は UTF-8 として受け取る（`[Console]::OutputEncoding` を一時的に UTF-8 にする）。

### 4.2 Api 方式のアルゴリズム（`Get-PrSizeFromApi`）

1. イテレーション一覧を取得し、最大の `id` を最終イテレーションとする
2. その変更一覧を取得（`$compareTo` 省略 = 共通祖先との比較 = PR 全体）
3. `item.isFolder=true` を除き、除外パターンに一致しないものを数える

API 呼び出しは PR 1 件につき 2 回以上（変更が 2000 件を超えるとさらに増える）。

### 4.3 `Initialize-GitRepository`

```
path = {LocalRepoRoot}\{リポジトリ名}
path が無い:
    AutoClone=$false → 例外
    git clone --mirror {CloneExtraArgs} {remoteUrl} {path}
path がある:
    git rev-parse --git-dir で git リポジトリか確認
    FetchBeforeDiff=$true → git fetch origin --prune（失敗しても警告のみ）
```

### 4.4 `Test-PathExcluded` / `Get-PrSizeCategory`

- パスは `\`→`/` に変換し、先頭の `/` を取ってから、パターンと `-like` で比較する。
- サイズ区分は「行数があれば `MaxLines`、無ければ `MaxFiles`」で、上から順に `値 <= 上限` の最初の区分。上限 `$null` は無制限。

## 5. Aggregator.ps1

### `Test-PullRequestIncluded -PullRequest -Config -Range` → bool

次をすべて満たすと `$true`:

1. 基準日（`DateBasis`）があり、`FromUtc <= 基準日 < ToUtcExclusive`
2. `ExcludeDrafts=$true` なら `isDraft` が `$true` でない
3. `TargetBranches` が空でなければ、`targetRefName` がそれに含まれる
4. `createdBy.displayName` も `createdBy.uniqueName` も `ExcludeAuthors` に含まれない

### `ConvertTo-PrRecord` → 明細レコード

列の一覧と計算式は [06 出力仕様](06_出力仕様.md#1-prscsv) を参照。主な変換:

- 日時: UTC → 設定タイムゾーン、`yyyy-MM-dd HH:mm`
- `Period`: 基準日を設定タイムゾーンに変換 → `Get-PeriodStart` → `Get-PeriodLabel`
- `LeadTimeHours`: `round((closed − created).TotalHours, 2)`
- `ReviewerCount`: `isContainer=true`（グループ）を除いたレビュアー数
- `ApprovedCount`: そのうち `vote >= 5`
- ブランチ名: 先頭の `refs/heads/` を除く

### 期間の計算

| 関数 | 内容 |
|---|---|
| `Get-PeriodStart` | Day: その日 / Week: `(7 + 曜日 − 開始曜日) % 7` 日戻す / Month: 1 日 |
| `Get-PeriodLabel` | Month: `yyyy-MM`、それ以外: `yyyy-MM-dd` |
| `Get-PeriodStarts` | `FromLocal` を含む期間の開始日から、`ToLocalExclusive` 未満まで、すべての期間開始日を列挙 |

> 期間の最初と最後は、集計期間で切れて「部分的な週/月」になることがある。
> 例: 9/3（木）〜 の集計で週単位なら、最初の週（8/31〜）は 9/3〜9/6 の 4 日分だけ。比較するときは注意する。

### `Get-PeriodSummary` / `Get-AuthorSummary`

- リポジトリが複数のときは、リポジトリ別のグループに加えて `(ALL)` グループを作る（`Get-RecordGroups`）。
- 統計関数（`Get-Median`, `Get-Average`, `Get-Sum`）は `$null` を除いて計算し、値が無ければ `$null`（CSV では空欄）。
- 中央値: 件数が偶数なら中央 2 つの平均。小数 2 桁に丸める。

## 7. テスト（tests/Run-Tests.ps1）

Pester を使わない簡易ランナー（Windows 標準の Pester 3.4 と最新の 5.x で書き方が違うため）。

| 分類 | 主なテスト |
|---|---|
| Config | 設定ファイルの読み込み、引数の上書き、不正値のまとめてエラー、期間の UTC 変換、日時変換 |
| SizeCalculator | パス除外、リネーム表記、numstat 集計、サイズ区分 |
| Aggregator | 週/月の開始日、中央値、対象判定（境界・Draft・ブランチ・作成者）、レコード化、0 件期間、`(ALL)` 行 |
| Git 方式 | 一時フォルダに実際の git リポジトリを作り、通常マージ・フォールバック・コミット無しを検証 |

テストを追加するときは `It '名前' { ... }` の形で書き、`Assert-Equal 期待値 実際値` / `Assert-Throws { ... }` を使う。
