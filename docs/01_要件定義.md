# 01. 要件定義

## 1. 目的

Azure DevOps 上のリポジトリ `SampleRepo` について、PR（Pull Request）の **頻度** と **サイズ** を定量的に把握する。

想定する使い方:

- 開発の流れ（PR が細かく頻繁に出ているか、大きな PR が溜まっていないか）を週次・月次で振り返る
- 「PR を小さくする」などの改善施策の効果を、前後比較で確認する
- レビュー待ち時間（リードタイム）が長くなっていないかを見る

## 2. スコープ

### 2.1 対象

| 項目 | 値（初期設定） | 変更方法 |
|---|---|---|
| 組織 (Organization) | `contoso` | `config/settings.psd1` の `Organization` |
| プロジェクト | `SampleProject` | `Project` |
| リポジトリ | `SampleRepo` | `Repositories`（複数可） |
| PR の状態 | 完了（completed） | `Statuses` |
| 期間 | 実行日を含む直近 90 日 | `FromDate` / `ToDate` / `LastNDays` |

### 2.2 対象外（今回は作らない）

- グラフの描画（CSV を Excel / Power BI で可視化する前提）
- レビューコメント数、初回レビューまでの時間（[将来拡張](#6-将来拡張の候補)を参照）
- 定期実行の仕組み（必要ならタスクスケジューラで `Invoke-PrMetrics.ps1` を実行する）
- Azure DevOps へのデータ書き込み（**読み取りのみ**）

## 3. 指標の定義

> ここで決めた定義が、ツールの計算の基準になります。定義を変える場合は、この表とコードを一緒に更新してください。

### 3.1 頻度

| 指標 | 定義 | 出力先 |
|---|---|---|
| PR 件数 | 期間（日/週/月）内に **基準日** がある PR の件数 | `summary_by_period.csv` の `PrCount` |
| 基準日 | `DateBasis='Closed'`（既定）なら完了日時（`closedDate`）、`'Created'` なら作成日時（`creationDate`） | 設定 `DateBasis` |
| 作成者数 | 期間内に PR を出した作成者の人数（重複なし） | `AuthorCount` |
| 週あたり PR 件数（作成者別） | 作成者の PR 件数 ÷（集計日数 ÷ 7） | `summary_by_author.csv` の `PrPerWeek` |

- 期間の区切りは設定したタイムゾーン（既定: 日本時間）で判定する。
  例: 9/30 23:30（日本時間）に完了した PR は 9 月分になる。
- PR が 0 件の期間も「0 件」の行として出力する（グラフにしたとき途切れないように）。
- 週は `WeekStartDay`（既定: 月曜）から始まる 7 日間。ラベルは週の開始日（例: `2026-09-28`）。

### 3.2 リードタイム

| 指標 | 定義 |
|---|---|
| リードタイム（時間） | `closedDate − creationDate`（時間単位・小数 2 桁） |
| 期間の集計値 | 中央値（`LeadTimeMedianH`）と平均値（`LeadTimeAvgH`） |

- 中央値を主指標とする（一部の長期放置 PR で平均が大きく歪むため）。
- Draft で作成してから公開した PR は、Draft の期間もリードタイムに含まれる（API に公開日時が無いため）。

### 3.3 サイズ

| 指標 | 定義 |
|---|---|
| 変更ファイル数 (`FilesChanged`) | PR が変更したファイル数（除外パターンに一致したファイルは数えない） |
| 追加行数 / 削除行数 (`LinesAdded` / `LinesDeleted`) | `git diff --numstat` の値の合計（Git 方式のみ） |
| 変更行数 (`LinesChanged`) | 追加行数 ＋ 削除行数 |
| サイズ区分 (`SizeCategory`) | 変更行数（無ければファイル数）を閾値で XS/S/M/L/XL に分類 |

- **「PR の変更」とは、PR をマージしたことでマージ先ブランチに持ち込まれた差分** を指す。
  マージ先ブランチ側で同時期に進んだ変更は含めない（詳細: [05 詳細設計](05_詳細設計.md#4-sizecalculatorps1)）。
- バイナリファイルは行数を数えられないため、ファイル数にだけ数え、`BinaryFiles` に件数を出す。
- 自動生成物・ビルド成果物（`*.hex`, `*.bin` など）は `ExcludePathPatterns` で除外する（ファームウェア開発では行数が実態とかけ離れて大きくなるため）。

サイズ区分の既定の閾値:

| 区分 | 変更行数 | 変更ファイル数（行数が無い場合） |
|---|---|---|
| XS | 〜10 | 〜1 |
| S | 〜50 | 〜3 |
| M | 〜250 | 〜10 |
| L | 〜1000 | 〜30 |
| XL | 1001〜 | 31〜 |

## 4. 機能要件

| ID | 要件 |
|---|---|
| F-01 | 設定ファイル 1 つで、組織・プロジェクト・リポジトリ（複数）・期間・絞り込み条件を変更できる |
| F-02 | コマンドライン引数で、期間・リポジトリ・サイズ計算方式を一時的に上書きできる |
| F-03 | 指定期間・指定ステータスの PR を全件取得する（ページングに対応する） |
| F-04 | Draft・マージ先ブランチ・作成者（Bot など）で対象を絞り込める |
| F-05 | PR サイズの計算方式を選べる（Git: 行数まで / Api: ファイル数のみ / None: 計算しない） |
| F-06 | 明細・期間別集計・作成者別集計を CSV で出力する |
| F-07 | 接続確認モードで、認証・権限・API の対応状況・git の認証を事前に確認できる |
| F-08 | API の生データを保存し、後から API を呼ばずに再集計できる（`SaveRawJson` / `-ReplayDir`） |
| F-09 | 一部の PR でサイズ計算に失敗しても処理全体は止めず、失敗理由を明細に残す |

## 5. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| N-01 | 環境 | 会社 PC 標準の **Windows PowerShell 5.1** で動くこと（PowerShell 7 でも動くこと）。追加モジュールのインストールを不要とする |
| N-02 | セキュリティ | PAT をファイル・ログ・画面・URL に出力しない。設定ファイルに PAT を書かせない |
| N-03 | セキュリティ | Azure DevOps に対して読み取り操作だけを行う |
| N-04 | 文字コード | 日本語（PR タイトル・作成者名・ファイル名）が文字化けしないこと。CSV は Excel で開ける UTF-8（BOM 付き） |
| N-05 | 信頼性 | API の一時的なエラー（429 / 5xx / 通信断）は自動で再試行する |
| N-06 | 保守性 | 設定項目を追加しやすい構成にする。処理ごとにファイルを分け、関数単位でテストできるようにする |
| N-07 | 追跡性 | 実行ごとにフォルダを分けて出力し、実行条件（`run_info.json`）を残す |
| N-08 | 性能 | 数百件程度の PR を数分以内で処理できること（Git 方式の初回 clone は除く） |

## 6. 前提・制約

- PAT（Personal Access Token）を発行できること。必要なスコープは **Code (Read)** だけ。
- Azure DevOps の **Analytics（OData）には PR のデータが無い** ため、REST API を使う。
- REST API には **PR の変更行数を直接返す項目が無い**。行数は git の差分から計算する（Git 方式）。
- Git 方式では、PR のマージ関連コミットがローカル clone から取得できる必要がある。
  完了後にソースブランチが削除された PR は、マージ先の履歴にあるコミット（`lastMergeCommit`）で計算する。
  → 実環境での確認が必要（[07 動作確認手順](07_動作確認手順.md) の「要確認事項」）。
