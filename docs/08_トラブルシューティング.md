# 08. トラブルシューティング

まず `-Verbose` を付けて再実行すると、呼び出した API の URL と git コマンドが表示されます（PAT は表示されません）。

```powershell
.\Invoke-PrMetrics.ps1 -Mode TestConnection -Verbose
```

## エラー一覧

| ID | 表示されるメッセージ（抜粋） | 原因 | 対処 |
|---|---|---|---|
| E-01 | `API が JSON 以外を返しました(HTTP 203, text/html)` | PAT が無効・期限切れ。または組織名の誤り | PAT を作り直す。`$env:AZDO_PAT` に前後の空白・改行が入っていないか確認。`Organization` の綴りを確認 |
| E-02 | `HTTP 401` | PAT のスコープ不足・期限切れ・別組織用の PAT | PAT の Organization が `contoso`（または All accessible organizations）で、Code: Read があるか |
| E-03 | `HTTP 403` | PAT の作成者にリポジトリの閲覧権限が無い | ブラウザで同じユーザーでリポジトリを開けるか確認 |
| E-04 | `HTTP 404` | 組織・プロジェクト・リポジトリ名の誤り | ブラウザの URL `https://dev.azure.com/{組織}/{プロジェクト}/_git/{リポジトリ}` と設定を照合。ハイフン `-` とアンダースコア `_` の違いに注意 |
| E-05 | `HTTP 400` | API が未対応のパラメーター | `UseServerSideDateFilter = $false`。Azure DevOps Server なら `ApiVersion` を下げる（例 `'6.0'`） |
| E-06 | `HTTP （空）... 通信できませんでした` / `リモート サーバーに接続できません` | ネットワーク・プロキシ | ブラウザで dev.azure.com が開けるか。社内プロキシがあるなら `Proxy` に設定 |
| E-07 | `基になる接続が閉じられました` / `SSL/TLS` | 5.1 の TLS 設定 | スクリプトは TLS1.2 を有効化しているが、PC のポリシーで無効化されている場合は情報システム部門に確認。PowerShell 7 で実行してみる |
| E-08 | `設定ファイルに誤りがあります` | 設定値の誤り | メッセージの各行を直す。日付は `yyyy-MM-dd` |
| E-09 | `Import-PowerShellDataFile` の構文エラー / 日本語が化ける | 設定ファイルの BOM が消えた、`'` の閉じ忘れ、`,` の書き間違い | UTF-8 with BOM で保存し直す。配列は `@('a', 'b')`、ハッシュ内の区切りは `;` |
| E-10 | `git clone に失敗しました` / git 認証 NG | git の認証・プロキシ | 下記「git の認証」 |
| E-11 | `git が見つかりません` | Git for Windows 未インストール、PATH 未設定 | インストールするか、`SizeMethod = 'Api'` / `'None'` |
| E-12 | `ローカルリポジトリがありません` | `AutoClone=$false` で clone が無い | `LocalRepoRoot` のパスを確認、または `AutoClone=$true` |
| E-13 | `このシステムではスクリプトの実行が無効になっているため` | 実行ポリシー | `powershell -ExecutionPolicy Bypass -File ...` で実行。ダウンロードしたファイルは `Unblock-File` |
| E-14 | `Replay 用ファイルがありません` | `-ReplayDir` のフォルダに `raw_pullrequests_{repo}.json` が無い | `SaveRawJson=$true` で実行したフォルダを指定する |

## 症状別

### 件数が Azure DevOps の画面と合わない

1. 画面の件数がどの日付で数えたものか確認する（作成日 / 完了日）。ツールは `DateBasis` で切り替え。
2. `Statuses` に `abandoned` が入っていないか（画面の Completed タブは completed のみ）。
3. `ExcludeDrafts` / `TargetBranches` / `ExcludeAuthors` で除外されていないか。
4. `run_info.json` の `Fetched`（取得件数）と `Included`（対象件数）を比べる。
5. それでも合わなければ `UseServerSideDateFilter = $false` で実行して件数が変わるか確認（変わるならサーバー側の絞り込みの挙動差。`$false` を使う）。

### サイズが `unavailable` になる PR が多い

`SizeNote` を確認する。

| SizeNote | 意味 | 対処 |
|---|---|---|
| `target..merge: コミット未取得 xxxxxxxx` | マージコミットがローカルに無く、fetch でも取れない | `FetchBeforeDiff=$true` で最新化されているか。続けて `base...source` も失敗しているなら、[07 動作確認手順](07_動作確認手順.md) の「Q-3 で問題があった場合の改修方針」 |
| `PR にマージ関連のコミットIDがありません` | API がコミット情報を返していない（マージ競合のまま完了・古い PR など） | 件数が少なければ許容。多ければ Api 方式との併用を検討 |
| `git diff 失敗 ...` | git のエラー | メッセージ参照。`--filter=blob:none` の clone で認証が切れている場合は `GitUsePatHeader=$true` |

### 行数が想像より大きい / 小さい

- 自動生成ファイル・ライブラリの取り込み・改行コードの一括変換などが含まれていないか、`prs.csv` で `LinesChanged` の大きい PR を開いて確認する。
  必要なら `ExcludePathPatterns` に追加する。
- バイナリは行数に含まれない（`BinaryFiles` を参照）。
- ファイルの移動（リネーム）は、内容が似ていれば移動として扱われ、行数は小さくなる（`git diff -M`）。

### 実行が遅い

| 原因 | 対処 |
|---|---|
| 初回 clone | 2 回目以降は fetch だけなので速くなる。`CloneExtraArgs = @('--filter=blob:none')` も検討 |
| 一覧にマージコミット情報が無く、PR 個別取得している | 接続確認の INFO 行で確認。仕様なので期間を短くする |
| Api 方式 | PR 1 件につき API 2 回以上。Git 方式のほうが速い |
| `UseServerSideDateFilter=$false` | 全 PR を取得するため。`$true` で動くなら `$true` に |
| 期間が長い | `-FromDate` / `-ToDate` で分割して実行 |

## git の認証

Git 方式は、PC の **Git Credential Manager（GCM）** の認証情報を使って clone/fetch します（既定）。

1. まず手動で確認:
   ```powershell
   git ls-remote --heads https://contoso@dev.azure.com/contoso/SampleProject/_git/SampleRepo
   ```
   - ブラウザのサインイン画面が出たらサインインする（以後 GCM が記憶）
   - ブランチ一覧が表示されれば OK
2. プロキシがある場合:
   ```powershell
   git config --global http.proxy http://proxy.example.co.jp:8080
   ```
3. それでもうまくいかない場合は、`GitUsePatHeader = $true` にすると、環境変数の PAT を git にも使う（その実行の間だけ。git の設定には保存されない）。

## 調査用データの取り方

Copilot やチームに相談するときは、次の情報をそろえると速く解決します（**PAT・個人名は伏せる**）。

1. `$PSVersionTable.PSVersion` と `git --version`
2. 実行したコマンドと、表示されたエラー全文（`-Verbose` 付き）
3. `run_info.json`
4. `SaveRawJson = $true` で取得した `raw_pullrequests_*.json` の PR 1 件分（作成者名・メールは伏せる）
