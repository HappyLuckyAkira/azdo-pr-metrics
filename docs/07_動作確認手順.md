# 07. 動作確認手順（会社 PC）

この手順は、上から順に進めると「どこまで動いているか」が分かるように並べています。
各ステップの **期待結果** と違ったら、そこで止めて [08 トラブルシューティング](08_トラブルシューティング.md) を見るか、Copilot に相談してください（[09 Copilot 活用ガイド](09_GitHubCopilot活用ガイド.md) のプロンプト例を使えます）。

## 開発 PC での確認結果（参考）

このツールは作成時に、次の環境と条件で確認済みです（実際の Azure DevOps には接続していません）。

| 確認内容 | 結果 |
|---|---|
| 単体テスト 19 件（Windows PowerShell 5.1 / PowerShell 7.6） | すべて成功 |
| Azure DevOps API の**模擬サーバー**を使った通し実行（Git / Api / None / Replay / 接続確認） | 期待どおり |
| ページング・日本語タイトル・CSV の BOM・期間境界・squash/通常マージの行数 | 期待どおり |
| エラー時（PAT 誤り＝203、リポジトリ名誤り＝404、接続不可）のメッセージ | 期待どおり |

**つまり、実際の Azure DevOps の応答で確認していないのは、「要確認事項」（最後の章）だけです。**

| No | 作業 | 確認方法 | 期待結果 |

## Step 1. 単体テスト（接続なし）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
```

**期待結果**: 最後に `結果: 19 件すべて成功`（git が無い場合は Git 方式の 3 件が SKIP になり 16 件）

> `-ExecutionPolicy Bypass` は、この 1 回の実行だけ実行ポリシーを緩める指定です（PC の設定は変わりません）。社内ルールで禁止されている場合は、情報システム部門に確認してください。

## Step 2. PAT を設定

```powershell
$env:AZDO_PAT = '<発行した PAT>'
```

- この設定は**今開いている PowerShell ウィンドウの間だけ**有効です。
- 毎回入力したくない場合（定期実行など）は、ユーザー環境変数に登録します:
  `[Environment]::SetEnvironmentVariable('AZDO_PAT', '<PAT>', 'User')`（新しいウィンドウから有効）
- 設定しなくても、実行時に入力を求められます。

**データの確認**（ここが大事）:

## Step 7. Git 方式でサイズ（行数）

```powershell
# 初回は clone が走ります（リポジトリが大きいと数分〜数十分）
powershell -NoProfile -ExecutionPolicy Bypass -File .\Invoke-PrMetrics.ps1 -FromDate 2026-09-01 -ToDate 2026-09-30
```

> リポジトリが大きい場合: `CloneExtraArgs = @('--filter=blob:none')` にすると clone が軽くなります（差分計算時に必要な分だけ取得するので、実行は少し遅くなります）。
> 既に clone がある場合: [04 設定ファイル仕様](04_設定ファイル仕様.md) の「例 4」のとおり `LocalRepoRoot` を指定します。

**期待結果**:
- `LinesAdded` / `LinesDeleted` / `LinesChanged` に値が入る
- `SizeSource` がほぼすべて `git:target..merge`
- 終了時に「サイズを計算できなかった PR が N 件」の警告が**出ない**、または少数

| No | 確認 | 方法 |
|---|---|---|
| 7-1 | 行数が正しいか | 下の「行数の照合方法」で 3 件程度を照合 |
| 7-2 | squash の PR も正しいか | `MergeStrategy=squash` の PR を 1 件以上照合 |
| 7-3 | `unavailable` の PR | `SizeNote` を見て理由を確認（多い場合は要確認事項 Q-3） |
| 7-4 | 除外パターン | `ExcludedFiles` が 1 以上の PR を見て、除外したいファイルだけが除外されているか |

**行数の照合方法**

PR 画面では、ファイルごとの差分は見られますが、PR 全体の合計行数は表示されないことがあります。次のどちらかで照合します。

```powershell
# 方法 A: ローカル clone で直接計算（prs.csv の PR について）
cd .\repos\SampleRepo
git diff --shortstat <lastMergeTargetCommit> <lastMergeCommit>
#   → " 5 files changed, 120 insertions(+), 30 deletions(-)" を LinesAdded/LinesDeleted と比べる
#     （除外パターンに一致したファイルの分だけ差が出るのは正常）
```

- 方法 B: PR 画面の「Files」タブで、小さめの PR（数ファイル）の追加・削除行を目で数える

コミット ID は `SaveRawJson = $true` で実行し、`raw_pullrequests_SampleRepo.json` から確認できます。

## 要確認事項（実環境でしか確認できないこと）

| No | 確認したいこと | なぜ不確か | 確認方法 | 結果が違ったときの対応 |
|---|---|---|---|---|
| Q-1 | PR 一覧 API で `searchCriteria.minTime/maxTime/queryTimeRangeType` が使えるか | 比較的新しいパラメーターのため | Step 4 の「期間指定(サーバー側)」が OK か。さらに `run_info.json` の `Fetched` が期間外の PR を大量に含んでいないか | `UseServerSideDateFilter=$false` |
| Q-2 | PR 一覧の各要素に `lastMergeCommit` 等が含まれるか | ドキュメント上は含まれるが、一覧では省略される項目がある | Step 3 / Step 4 の INFO 行 | 対応不要（ツールが個別取得で補う。遅くなるだけ） |
| Q-3 | 完了した PR（特に squash・ソースブランチ削除済み）の `lastMergeCommit` が、clone から取得できるか | squash の場合、マージ時の「プレビュー用マージコミット」と実際にマージ先に入ったコミットが別物の可能性がある | Step 7 で `SizeSource` がほぼ `git:target..merge` になるか。`unavailable` の `SizeNote` に「コミット未取得」が多くないか | 下記「Q-3 で問題があった場合」 |
| Q-4 | squash の PR の行数が正しいか | Q-3 と同じ | Step 7-2 の照合 | 同上 |
| Q-5 | 社内プロキシ・認証環境で git の clone/fetch ができるか | 環境依存 | Step 4 の「git 認証」 | 08 の E-10、または `GitUsePatHeader=$true` |
| Q-6 | `isDraft`・`completionOptions` が返るか | 古い PR では欠けることがある | `prs.csv` の `IsDraft` / `MergeStrategy` | 対応不要（空欄になるだけ） |

### Q-3 で問題があった場合の改修方針（Copilot に依頼する内容）

1. **まず事実を確認**: `unavailable` になった PR の 1 件について、次を調べる
   - `git -C repos\SampleRepo log --oneline --grep "Merged PR <PR番号>"` で、マージ先にある実際のマージ/squash コミットを探す（Azure DevOps の既定のマージコミットメッセージは `Merged PR 123: タイトル`）
   - そのコミット ID と、API の `lastMergeCommit.commitId` が同じか
2. **違っていた場合の改修案**: `Get-PrSizeFromGit` に戦略 0 を追加する
   - マージ先ブランチの履歴から `Merged PR {pullRequestId}:` で始まるコミットを探し、`git diff {そのコミット}^1 {そのコミット}` で計算する
   - `SizeSource = 'git:merged-commit'` とする
   - 単体テスト（`tests/Run-Tests.ps1`）に、メッセージで探すケースを追加する
3. **別案**: Api 方式との併用（行数は諦めて、ファイル数で区分する）
