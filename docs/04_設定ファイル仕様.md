# 04. 設定ファイル仕様

ファイル: `config/settings.psd1`

## 1. 書き方の基本

```powershell
@{
    文字列     = 'abc'                  # シングルクォートで囲む
    数値       = 90
    真偽値     = $true                  # または $false
    配列       = @('a', 'b')            # 要素 1 個でも @('a') と書く
    空の配列   = @()
    空文字     = ''
    改行で配列 = @(
        'a'
        'b'
    )
    ハッシュ   = @{ Name = 'XS'; MaxLines = 10 }
}
```

- `#` 以降はコメント。
- 書けるのは値だけ（変数・関数呼び出しは書けない）。読み込みは `Import-PowerShellDataFile` で行うので、任意コードは実行されない。
- **ファイルの文字コードは UTF-8（BOM 付き）のまま保存する**。BOM が無いと、Windows PowerShell 5.1 でコメントの日本語が化けて、読み込みエラーになることがある。
  VS Code では、右下のエンコード表示が「UTF-8 with BOM」になっていることを確認する。
- 書かなかった項目は `src/Config.ps1` の `$script:PrMetricsDefaultConfig` の既定値が使われる。

## 2. 設定項目一覧

### 2.1 接続先

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `Organization` | string | （必須） | 組織名。`https://dev.azure.com/{ここ}` |
| `Project` | string | （必須） | プロジェクト名 |
| `Repositories` | string[] | （必須） | 対象リポジトリ名。複数指定すると、リポジトリ別と全体 `(ALL)` で集計 |
| `BaseUrl` | string | `https://dev.azure.com` | オンプレの場合 `https://{server}/tfs` |
| `ApiVersion` | string | `7.1` | REST API のバージョン |
| `PatEnvVarName` | string | `AZDO_PAT` | PAT を入れる環境変数名 |
| `Proxy` | string | `''` | プロキシ URL。空なら OS の設定 |
| `ProxyUseDefaultCredentials` | bool | `$true` | プロキシ認証に Windows ログオン資格情報を使う |

### 2.2 集計期間

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `FromDate` | string | `''` | 開始日 `yyyy-MM-dd`（その日の 0:00 から） |
| `ToDate` | string | `''` | 終了日 `yyyy-MM-dd`（**その日を含む**） |
| `LastNDays` | int | `90` | `FromDate` が空のとき、終了日から遡る日数 |
| `DateBasis` | string | `Closed` | `Closed`=完了日、`Created`=作成日 で期間判定 |
| `TimeZoneId` | string | `Tokyo Standard Time` | 期間判定・表示のタイムゾーン（Windows のタイムゾーン ID） |
| `PeriodUnit` | string | `Week` | `Day` / `Week` / `Month` |
| `WeekStartDay` | string | `Monday` | 週の開始曜日（`Sunday` 〜 `Saturday`） |

期間の決まり方:

| FromDate | ToDate | 対象期間 |
|---|---|---|
| 空 | 空 | （今日 − LastNDays + 1）〜 今日 |
| 指定 | 空 | FromDate 〜 今日 |
| 空 | 指定 | （ToDate − LastNDays + 1）〜 ToDate |
| 指定 | 指定 | FromDate 〜 ToDate |

### 2.3 対象 PR の絞り込み

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `Statuses` | string[] | `@('completed')` | `completed` / `abandoned` / `active` |
| `TargetBranches` | string[] | `@()` | マージ先ブランチ（`refs/heads/` から書く）。空なら全て |
| `ExcludeDrafts` | bool | `$true` | Draft PR を除外 |
| `ExcludeAuthors` | string[] | `@()` | 除外する作成者の表示名 or `uniqueName`（完全一致） |
| `UseServerSideDateFilter` | bool | `$true` | API 側でも期間で絞る。400 エラーになる環境では `$false` |

### 2.4 サイズ計算

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `SizeMethod` | string | `Git` | `Git`（行数まで）/ `Api`（ファイル数のみ）/ `None` |
| `LocalRepoRoot` | string | `.\repos` | clone 置き場。`{LocalRepoRoot}\{リポジトリ名}` を使う。相対パスはツールのフォルダ基準 |
| `AutoClone` | bool | `$true` | 無ければ `git clone --mirror` する |
| `CloneExtraArgs` | string[] | `@()` | clone の追加引数。例 `@('--filter=blob:none')` |
| `FetchBeforeDiff` | bool | `$true` | 実行前に `git fetch origin --prune` |
| `FetchMissingCommits` | bool | `$true` | ローカルに無いコミットを個別に fetch する |
| `GitUsePatHeader` | bool | `$false` | git の認証に PAT を使う（既定は PC の資格情報マネージャー） |
| `ExcludePathPatterns` | string[] | `@()`（設定ファイルでは `*.hex` 等） | サイズ計算から除外するパス（ワイルドカード） |
| `SizeCategories` | hashtable[] | XS/S/M/L/XL | サイズ区分の定義（下記） |

**`ExcludePathPatterns` の書き方**

- パスはリポジトリ直下からの相対パスで、区切りは `/`（`\` で書いても自動変換される）。
- `*` は `/` も含めて任意の文字列に一致する（PowerShell の `-like` 演算子）。大文字・小文字は区別しない。

| パターン | 一致する例 | 一致しない例 |
|---|---|---|
| `*.hex` | `out/app.hex`, `a.HEX` | `hex/readme.txt` |
| `Generated/*` | `Generated/a.c` | `src/Generated/a.c` |
| `*/Generated/*` | `src/Generated/a.c` | `Generated/a.c` |
| `ThirdParty/*` | `ThirdParty/lib/x.c` | — |

**`SizeCategories` の書き方**

```powershell
SizeCategories = @(
    @{ Name = 'XS'; MaxLines = 10;    MaxFiles = 1     }
    @{ Name = 'S';  MaxLines = 50;    MaxFiles = 3     }
    @{ Name = 'M';  MaxLines = 250;   MaxFiles = 10    }
    @{ Name = 'L';  MaxLines = 1000;  MaxFiles = 30    }
    @{ Name = 'XL'; MaxLines = $null; MaxFiles = $null }   # 最後は上限なし
)
```

- 上から順に判定し、値が `MaxLines` **以下** の最初の区分になる。
- 行数が取れない（Api 方式、または計算失敗）場合は `MaxFiles` で判定する。両方取れない場合は空欄。
- 区分の数・名前は自由に変えてよい。`summary_by_period.csv` の `Size_{Name}` 列も自動で変わる。

### 2.5 出力・通信

| 項目 | 型 | 既定値 | 説明 |
|---|---|---|---|
| `OutputDir` | string | `.\output` | 出力先。実行ごとに `yyyyMMdd_HHmmss` フォルダを作る |
| `SaveRawJson` | bool | `$false` | API の PR 一覧を `raw_pullrequests_{repo}.json` として保存 |
| `PageSize` | int | `100` | PR 一覧の 1 ページの件数（1〜1000） |
| `MaxRetry` | int | `3` | 再試行回数 |
| `RetryWaitSeconds` | int | `5` | 初回の再試行までの待ち秒数（以降 2 倍ずつ） |

## 3. コマンドライン引数による上書き

| 引数 | 上書きする設定 | 例 |
|---|---|---|
| `-ConfigPath` | （使う設定ファイル自体） | `-ConfigPath .\config\settings_tools.psd1` |
| `-FromDate` | `FromDate` | `-FromDate 2026-04-01` |
| `-ToDate` | `ToDate` | `-ToDate 2026-09-30` |
| `-Repositories` | `Repositories` | `-Repositories SampleRepo,SampleTools` |
| `-SizeMethod` | `SizeMethod` | `-SizeMethod None` |
| `-Mode` | — | `Collect`（既定）/ `TestConnection` |
| `-ReplayDir` | — | 保存済み JSON で再集計 |
| `-Verbose` | — | API の URL・git コマンドを表示 |

## 4. 変更例

### 例 1: 上期（4〜9 月）を月単位で
```powershell
FromDate   = '2026-04-01'
ToDate     = '2026-09-30'
PeriodUnit = 'Month'
```

### 例 2: main と release ブランチへのマージだけ
```powershell
TargetBranches = @('refs/heads/main', 'refs/heads/release')
```

### 例 3: 自動化アカウントの PR を除外
```powershell
ExcludeAuthors = @('Project Collection Build Service (contoso)', 'bot@example.co.jp')
```
作成者の正確な名前は、一度実行して `prs.csv` の `Author` / `AuthorId` 列で確認する。

### 例 4: 既存の作業用 clone（`D:\Repos\SampleRepo`）を使う
```powershell
LocalRepoRoot = 'D:\Repos'
AutoClone     = $false
```
作業ツリーのある通常の clone でもよい（`git fetch` しかしないので作業中の変更には影響しない）。

### 例 5: リポジトリごとに設定を分ける
`config/settings.psd1` をコピーして `config/settings_tools.psd1` を作り、`-ConfigPath` で指定する。

## 5. 設定項目を追加するときの手順（開発者向け）

1. `src/Config.ps1` の `$script:PrMetricsDefaultConfig` に既定値を追加
2. 配列の項目なら、`Import-PrMetricsConfig` の正規化対象リストに追加
3. 値の検証が必要なら `Test-PrMetricsConfig` に追加
4. `config/settings.psd1` にコメント付きで追加
5. この資料の 2 章に追記
6. `tests/Run-Tests.ps1` にテストを追加
